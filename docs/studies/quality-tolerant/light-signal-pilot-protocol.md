## Why this alternative and what it can establish

Phase01 full entropy+margin extraction averaged2.35-2.70ms in its timed component, while paired whole-request differences had large variation and session means-0.454/+7.266ms. The original1msmean/3msp95whole-request screen failed. Do not relabel it as passed.

This phase changes both instrumentation and measurement question. Drop expensive full-distribution log_softmax/exp/entropy. Measure two lower-cost current-logit groups: top-two relative margins and selected-token raw logits gathered at IDs already chosen by the frozen picker. A gather avoids another vocabulary-wide reduction; this is a source-complexity argument, not a measured success. Raw selected logits are NOT probabilities/calibrated confidence and are NOT invariant to an additive logit shift; that property is tested/documented. Margin is shift-invariant. Neither feature type is assumed predictive.

The primary collection-feasibility endpoint is synchronous extra extraction cost recorded inside each ready-output request. It includes GPU work, compact CPU transfer and host cue/signal summaries. The feature group starts after existing token/code CPU transfers and cheap-feature computation, and its own CPU transfer synchronizes its GPU work before return; it cannot escape the clock asynchronously. This measures the executed block, not its possible downstream clock/scheduling effects. Retain paired whole ready-output measurements separately, with more pairs and a large-penalty guard. No feature-cost endpoint establishes actual whole-controller savings; the eventual>=5%mean saving/positive paired bound/quality/fixed-comparator contract is unchanged.

This is a new bounded diagnostic, not a retry-until-green of phase01 or a new controller family. It reads no references or quality outcomes, trains nothing and changes no policy. The result only decides whether a small signal-discrimination collection is justified.
